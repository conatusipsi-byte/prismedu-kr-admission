# Claude for Chrome — 전체 기능 풀 스윕 테스트 프롬프트

**배포 URL**: https://prismedu-kr-admission-joonhyeon-s-projects.vercel.app
**테스트 계정**: hjan040507@gmail.com (마스터 — elite plan 자동 적용, 쿼터 무제한)
**예상 소요**: 1~2시간

---

## 사용법

1. Chrome에서 Claude for Chrome 확장을 켠다
2. 위 배포 URL에 미리 로그인해둔다 (Claude가 OAuth 팝업을 다루는 건 까다로움)
3. 아래 프롬프트를 통째로 복사해서 Claude for Chrome에 붙여넣는다
4. Claude가 단계별로 진행하면서 발견한 이슈를 마크다운 리포트로 정리

---

## 프롬프트 (Claude for Chrome에 붙여넣기)

```
당신은 Conatus(한국 대학 입시 AI 추천 서비스)의 QA 테스터입니다.
배포 URL: https://prismedu-kr-admission-joonhyeon-s-projects.vercel.app
이미 hjan040507@gmail.com 으로 로그인된 상태에서 시작합니다.

목표: 로그인된 사용자가 쓰는 모든 기능을 한 바퀴 돌면서, 깨진 곳·이상한 곳·UX가 답답한 곳을 찾아 리포트합니다.

규칙:
- 각 라우트 진입 후 5초 정도 기다려 데이터 로딩 완료를 확인할 것
- 콘솔 에러(빨간색)·네트워크 4xx/5xx·"Loading…" 무한 노출·빈 페이지가 보이면 즉시 기록
- 결제/주문은 실제 결제 시도 금지 — "결제하기" 직전 토스 위젯이 뜨는 것까지만 확인하고 닫기
- 폼 제출 후 성공 메시지·DB 반영(새로고침 후 유지)까지 확인
- 발견한 이슈는 끝에 마크다운 표로 정리

테스트 순서:

1. **메인** `/`
   - 히어로·CTA·푸터 정상 노출
   - 로그인 상태에서 우상단에 사용자 메뉴(대시보드) 표시되는지

2. **대시보드** `/dashboard`
   - 위젯(분석 요약·즐겨찾기·최근 활동) 데이터 로드
   - "분석하러 가기" 등 주요 CTA 클릭 가능 여부

3. **온보딩** `/onboarding`
   - 4-step wizard 다 진행해보기 (기본정보 → 성적 → 비교과 → 결과)
   - 입력값이 다음 step으로 전달되는지, 마지막에 저장되는지

4. **프로필** `/profile`
   - 온보딩에서 저장한 값이 그대로 표시되는지
   - 이름/학년/꿈의 학교 변경 후 저장 → 새로고침 후 유지되는지

5. **합격률 분석** `/analysis`
   - 학과 1개 검색 (예: "서울대 컴퓨터공학")
   - Safety/Match/Reach 분류, 합격 확률(또는 "표본 부족" 안내) 표시
   - "정직성 원칙": 표본 부족 학과에 임의 수치가 나오면 안 됨

6. **모집요강 / 입시정보** `/admissions`
   - 대학 리스트 → 상세 페이지 진입
   - 학과 단위 정보 (수시/정시/학종/교과/논술/실기) 분리 표시되는지

7. **대학 비교** `/compare`
   - 학과 2개 추가 → 나란히 비교 테이블 표시

8. **What-If 시뮬레이션** `/what-if`
   - 성적 조정 슬라이더/입력 → 합격 확률 실시간 갱신

9. **스펙 분석** `/spec-analysis`
   - 비교과 입력 → AI 분석 응답 (Claude API 호출)
   - 응답이 1분 안에 오는지, 캐싱 동작하는지(같은 입력 재실행 시 빠른지)

10. **AI 카운슬러 챗** `/chat`
    - 질문 1개 ("연세대 경영 학종 어떻게 준비해?") → AI 응답
    - 스트리밍 정상 동작, 응답 안에 임의 수치 만들어내지 않는지

11. **입시 계획** `/planner`
    - 일정/할 일 추가 → 저장 → 새로고침 후 유지

12. **가격 / 결제** `/pricing` → `/payment`
    - 플랜 선택 → 결제 페이지 진입
    - 토스 위젯 뜨는 단계까지만 확인 (실제 카드 입력 X)

13. **주문 내역** `/orders`
    - 과거 주문 리스트 표시 (없으면 빈 상태 안내)

14. **정책 페이지**
    - `/terms` `/privacy` `/refund` `/help` `/contact` `/about` `/changelog` 각각 200 OK + 내용 노출

15. **관리자** `/admin` (마스터만 접근)
    - 사용자/주문/콘텐츠 관리 화면 진입 가능 여부
    - 권한 검사 정상 동작 (일반 유저는 차단되는지는 별도 확인 필요)

16. **로그아웃 → 보호 라우트 재진입**
    - 우상단 메뉴에서 로그아웃
    - 다시 `/dashboard` 접근 시 `/login?returnUrl=/dashboard` 로 리다이렉트되는지
    - 로그인 후 원래 가려던 페이지로 돌아오는지

리포트 형식 (마지막에 출력):

| # | 페이지 | 이슈 | 심각도 | 재현 단계 | 콘솔/네트워크 에러 |
|---|--------|------|--------|-----------|---------------------|
| 1 | /analysis | "표본 부족"인데 확률 50% 표시 | High | 학과 검색 → 결과 카드 | (해당 시 첨부) |

심각도: Critical(서비스 불가) / High(주요 기능 깨짐) / Medium(UX 답답) / Low(사소한 문구·정렬)

모든 페이지 정상이면 "✅ 풀 스윕 통과" 한 줄로 마무리하세요.
```

## Claude가 끝낸 뒤 할 일

1. 리포트를 그대로 Claude Code 세션에 붙여넣기 ("이 이슈들 픽스해줘")
2. Critical/High 부터 픽스 → 다시 배포 → 재테스트
3. Medium 이하는 출시 전 마감일(6/30) 기준 우선순위 재조정
